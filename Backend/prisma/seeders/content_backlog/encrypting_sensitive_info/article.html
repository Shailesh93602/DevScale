Protecting Sensitive Information: Hash or Encrypt?

Sensitive data falls into two groups, and they need different tools. Data you only ever need to verify (passwords) should be hashed. Data you need to read back (API keys for third-party services, personal details) must be encrypted. Using a password hash such as bcrypt on an API key destroys it: you can never recover the key to use it.

1. Passwords: hash with a slow, salted algorithm

Store passwords with a password-hashing function such as argon2id or bcrypt. Both generate a random per-user salt and are deliberately slow, which makes brute-forcing a stolen database expensive. Never use a fast hash such as SHA-256 on its own for passwords.

import bcrypt from 'bcrypt';

const hash = await bcrypt.hash(password, 12); // salt is generated and stored inside the hash
const ok = await bcrypt.compare(attempt, hash);

2. Recoverable secrets: encrypt with an authenticated cipher

Encrypt values you must read later with an AEAD cipher such as AES-256-GCM (built into node:crypto). Use a fresh random 12-byte IV for every encryption and store the IV and auth tag next to the ciphertext. GCM's tag makes decryption fail if the ciphertext was tampered with.

import { createCipheriv, createDecipheriv, randomBytes } from 'node:crypto';

function encrypt(plaintext, key) {
  const iv = randomBytes(12);
  const cipher = createCipheriv('aes-256-gcm', key, iv);
  const data = Buffer.concat([cipher.update(plaintext, 'utf8'), cipher.final()]);
  return { iv, data, tag: cipher.getAuthTag() };
}

function decrypt({ iv, data, tag }, key) {
  const decipher = createDecipheriv('aes-256-gcm', key, iv);
  decipher.setAuthTag(tag);
  return Buffer.concat([decipher.update(data), decipher.final()]).toString('utf8');
}

3. Keep the key out of the database

Encryption is only as strong as the key's storage. Keep the 32-byte key in a key-management service (AWS KMS, GCP KMS, HashiCorp Vault) or at minimum an environment secret, never in the same database as the ciphertext and never in source control. Plan for rotation by storing a key id with each encrypted value.

Conclusion

Hash what you only verify, encrypt what you must read back, and protect the encryption key separately from the data it protects.
