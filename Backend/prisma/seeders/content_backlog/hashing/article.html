Understanding Hashing

A hash function maps input of any size to a fixed-size output (the digest). The same input always produces the same digest, and good cryptographic hashes make it infeasible to find the input from the digest or to find two inputs with the same digest.

1. What a hash guarantees, and what it does not

Digests are not unique: because infinitely many inputs map to a fixed number of outputs, collisions must exist. A secure hash such as SHA-256 only makes them infeasible to find. Older functions such as MD5 and SHA-1 have practical collision attacks and should not be used for security.

2. Hashing for integrity

Fast hashes such as SHA-256 are the right choice for checksums, content addressing and integrity checks, for example verifying that a downloaded file matches the published digest. To prove a message came from someone holding a secret key, use an HMAC rather than a bare hash.

3. Hashing passwords

Passwords need a different kind of hash: a deliberately slow, salted password-hashing function such as argon2id or bcrypt. A per-user random salt stops attackers from using precomputed tables, and the work factor makes each guess expensive. Fast hashes like SHA-256 let an attacker try billions of guesses per second.

Conclusion

Use SHA-256 or HMAC for integrity, argon2id or bcrypt for passwords, and remember that a hash is one-way: if you need the original value back, you need encryption, not hashing.
